# Feasibility analysis, 2026-10-06

## What happened since the last review

One day, two commits, since `9c08ec6` (2026-10-05). `dc99be0` deletes `docs/study-flows.md`, and
`29fcc09` builds most of E3.7, the plan bank. That second commit is the whole story of this review.
It adds a rules script (`propose.py`) that writes a `StudyPlan` for every one of the 54 E3.4 concepts
that has a gold `Question`, a 24-case phase-1 extension for the counterfactual ones, a review page with
the same flagging idea as the Parser's, and the code to apply a review export back onto the bank. All of
it is tested (`pytest` went from 1356 to 1718 passing), `ruff` and `mypy` are clean, and the 54+24
proposals already pass the bank's own coverage and topology checks.

I flipped E3.7 to 🔄, not ✅, and I want to be direct about why. This is the kind of distinction this
project's own status legend exists to protect. The task's Done bar is "reviewed on an HTML page," and
`test_plan_review.py` says, in its own docstring, that the real review is not in the repo. Nothing in
the commit contradicts that: no export file, no `corrected.json` with actual content, nothing. The
pipeline is a well-built proposal machine. It is not yet a reviewed gold bank. Calling it done because
the code that produces and validates the gold is done would be exactly the "related code exists" trap
the legend warns against.

## Pace against the calendar

The project keeps beating its own targets by wide margins, and this review does not change that
picture. M0 landed 4 days early, M1 a month early, M2 25 days ahead of its already re-baselined target.
Wave 1b (E3.11 → E5.14 → E3.7 → E5.2 → E5.3 → E5.4 → E9.1, targeted for the window 12 to 26 Oct) already
has two of its seven links finished (E3.11, E5.14) and a third built (E3.7) before that window has even
opened. Today is 6 Oct. Wave 1b's target is 26 Oct, 20 days out. At the rate the last week moved, five
E5.14 tickets in one day, the whole E3.7 pipeline in one day, closing out E3.7's review plus E5.2, E5.4
and E9.1 by 26 Oct reads as comfortable, not tight. No milestone deadline is at risk; none has been at
risk in any review so far.

That said, comfortable on points is not the same claim as comfortable on everything wave 1b needs. E5.2
and E5.4 are agent implementations starting from a 4-line placeholder, not refactors. The fast E5.14/E3.7
work this week was mostly rules code and schema plumbing, which this project is visibly fast at. An
agent that has to actually route and plan from a live model is a different kind of task, closer to
E5.1's Parser tuning, which took six prompt versions and a real held-out run to get right and still
missed its own bar (93.9 % vs ≥95 % intent agreement, E5.1's row). I would not extrapolate this week's
velocity onto E5.2 without discounting it.

## M2, M3, M6: the milestones the plan says must not be cut

M2 is done. M3 (Coordinator loop) is the one in flight, and it is where I would put my attention. E3.7
is built, E5.3 is 🔄, and E5.2, E5.4 and E9.1 are untouched placeholders or nonexistent. None of that is

## Risks actually observed this review, not restated from the docs

1. **The plan-bank review is a human bottleneck, not a build task, and the project has not needed one
   of those yet.** Every other "reviewed gold bank" so far (E3.4's requests, E5.1's Parser dev and
   held-out split) got its review folded into tuning work the maintainer was already doing by hand
   across several sessions. E3.7 is 78 items, 54 plans plus 24 phase-1 cases, sitting in one static HTML
   page, built in a single sitting, waiting for one sitting of actual review. That review cannot be
   delegated to another agent run the way the rules script was. It is specifically the step where a
   human checks the rules script's output, and the DoD is written that way on purpose: checking 78 plans
   against ADR-0025, ADR-0027 and ADR-0037 is not something a unit test can fully stand in for, even
   though this review's unit tests do check the narrow mechanical rules. It is the single concrete thing
   standing between E3.7 and ✅, and it needs calendar time set aside for it specifically, not more
   commits.
2. **E3.9 (evaluation budget doc) has a real external deadline closing in with zero visible progress.**
   The row's own text says it is needed before the ~24 Oct funding request, 18 days from today, and this
   review found no `docs/*budget*` file, same as the last two reviews. Unlike the internal wave target
   dates, this one is driven by something outside the plan's own calendar logic, a funding request to
   supervisors, so it does not get the same slack the rest of wave 1b enjoys.
3. **A small doc-hygiene paper cut.** `docs/study-flows.md` was deleted without updating the three
   places that still point at it: `tfm-work-plan.md`'s E9.1 row, and ADR-0025 and ADR-0030. Harmless
   today, but it is exactly the kind of stale cross-reference that gets expensive once E9.1's golden-path
   work actually starts and someone follows that link expecting a document that is still there.

## Recommendation

Keep going as planned. Nothing in this review's evidence calls for any step of the §5 fallback order.
The project is not just on pace, it is running ahead of a calendar that already has +121 points of
slack built in. The one thing I would actually act on, rather than just note, is to put the plan-bank
review on the calendar as its own piece of work this week, separate from and not blocked by any more
agent commits to `eval/plan_bank/`, since the pipeline that review needs is already finished and
waiting. And start E3.9 soon. It is small, 5 pts, but it is the one open item in wave 1b with a deadline
that answers to someone other than this plan's own schedule.
