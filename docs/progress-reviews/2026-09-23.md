## Concrete risks/bottlenecks observed this review

1. **Same-day scheduled review vs. local unpushed work is a real failure mode, not a one-off.**
   Today is the second time this class of issue has surfaced (the first was the PyPI-unreachable
   revert on 18 Sep, `cb58c7f`/`436ed4c`). If the review is meant to run unattended on a schedule, a
   push made *after* the scheduled trigger but *before* end of day will keep producing a false "no
   progress" entry. Not fixing the skill here (out of scope for a review), but flagging the pattern:
   push before end of day if a scheduled review is expected, or the timeline of dated entries will
   keep having gaps that don't reflect reality.
2. **The `EXP-01` funding block is now the tracker's oldest continuously-unresolved item** — three
   reviews (17, 18, 23 Sep) in a row have re-noted it without resolution. The amount is small enough
   (≈$3.9–5.8) that its persistence, not its size, is the signal: either it's genuinely stuck on an
   external approval (worth saying so explicitly rather than re-flagging weekly) or nobody is chasing
   it, and 22 Sep — a day with real E4 work happening anyway — would have been a natural moment to.
3. **`SUMO_HOME` is set in this local shell**, contrary to `CLAUDE.md`'s explicit requirement. Tests
   still passed (the warning didn't fail anything), but any numbers that matter — reproducibility
   claims, benchmark runs — should be produced from a shell with it unset, per the project's own rule.
4. **This tracker's E5 section had silently drifted from `tfm-work-plan.md`** for a full day (22 Sep,
   15:23 the ADR landed → 23 Sep, this review) before anyone (human or automated) caught it. Same
   class of paper-cut as the E3.2/E4.1 undercounting found on 18 Sep — worth treating "does the
   tracker's task list match the work-plan's task list" as its own explicit check in future reviews,
   not just "does each row's status match the evidence".
