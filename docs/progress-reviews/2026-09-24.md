## Risks actually observed

1. **ADR-0028 migration unscheduled** (above). This is the main one.
2. **Tuning on dev without having looked at held-out yet.** The prompt went through four versions against
   212 dev requests, and the last three failures were deliberately left untuned (the log says so, which
   is the right call). The held-out pass is the only honest number for the thesis, and it should be run
   once, as planned, before v4 gets any more edits. It costs about $0.10, under the $1 direct-run limit.
3. **ADR-0027 still Proposed**, while E5.12 (domain), E5.10 (arm-coverage validation) and now the
   Parser's arm structure metric all build on it. Accepting it is a paperwork step, but it should happen
   before E3.7/E5.2 bake it further into gold data.
4. **`EXP-01` funding** is unchanged. Its effect on the schedule is growing only because M2 gets closer.

## Recommendation

must-not-cut milestones have more slack than the plan assumed. The author has also noted that in the
worst case there is part-time room until the end of May for corrections after the 18 Feb delivery. That
is a real safety margin for thesis-quality fixes, but it shouldn't be planned into M2/M3/M5, which stay
on their dates.
